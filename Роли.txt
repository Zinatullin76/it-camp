Ты являешься Senior Software Architect и Senior Backend Developer.

Контекст проекта:

Мы разрабатываем компьютерный тренажерный комплекс (КТК) для установки ЭЛОУ-АВТ в рамках кейса IT-чемпионата Газпром нефти.

Проект представляет собой цифровой двойник технологической установки и включает:

- Backend (Python/FastAPI)
- Frontend (React)
- PostgreSQL
- Цифровой двойник технологического процесса
- Модуль сценариев
- Модуль оценки действий оператора
- AI-модуль
- REST API
- WebSocket

Необходимо реализовать полноценную ролевую модель (RBAC), максимально приближенную к промышленной системе.

Перед внесением любых изменений:

1. Полностью изучи архитектуру проекта.
2. Найди существующую систему авторизации.
3. Найди модели пользователей.
4. Найди middleware авторизации.
5. Найди все места, где используется текущая роль пользователя.
6. Определи, какие части проекта необходимо изменить.
7. Составь подробный план изменений.
8. Ничего не изменяй, пока не закончишь анализ.

После анализа реализуй следующую ролевую модель.

Роли:

1. Administrator
- управление пользователями
- управление ролями
- настройка системы
- просмотр логов
- управление справочниками
- управление оборудованием
- полный доступ

2. Instructor
- запуск тренировок
- выбор сценариев
- создание учебных групп
- наблюдение за оператором
- просмотр действий в реальном времени
- создание экзаменов
- просмотр статистики

3. Operator
- прохождение тренировок
- управление технологическим процессом
- работа с HMI
- просмотр своих результатов
- получение рекомендаций ИИ

4. Methodologist
- создание сценариев
- редактирование сценариев
- создание чек-листов
- создание критериев оценки
- управление библиотекой сценариев

5. Process Engineer
- настройка цифрового двойника
- изменение параметров оборудования
- изменение физических моделей
- настройка аварий
- изменение технологических ограничений

6. AI Analyst
- просмотр статистики ошибок
- анализ действий операторов
- управление рекомендациями ИИ
- настройка моделей оценки

7. Examiner
- проведение экзаменов
- просмотр итоговых результатов
- утверждение квалификации
- формирование отчетов

После анализа необходимо:

1. Спроектировать полноценную RBAC-модель.

2. Создать:

- Role
- Permission
- UserRole
- RolePermission

если они отсутствуют.

3. Все права должны проверяться через permissions, а не через if role == ...

Например:

can_manage_users
can_create_scenarios
can_start_training
can_view_statistics
can_manage_ai
can_manage_twin
can_take_exam
can_grade_exam
...

4. Если в проекте уже есть роли, аккуратно выполнить миграцию без поломки существующего функционала.

5. Обновить backend.

6. Обновить frontend.

7. Ограничить доступ к страницам.

8. Ограничить доступ к API.

9. Добавить проверки на сервере.

10. Добавить сиды с начальными ролями и правами.

11. Если потребуется изменить структуру базы данных — сначала объясни причину.

Требования:

- Не ломать существующую архитектуру.
- Следовать принципам SOLID.
- Следовать Clean Architecture.
- Не дублировать код.
- Использовать существующий стиль проекта.
- Не создавать новые файлы без необходимости.
- Перед каждым изменением объяснять, зачем оно нужно.
- После каждого этапа кратко описывать, что было сделано.

Если обнаружишь архитектурные проблемы, сначала предложи варианты решения, а затем приступай к реализации.
