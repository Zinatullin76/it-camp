# ЭЛОУ-АВТ Digital Twin — Расчётное ядро (Rigorous Core)

**Версия:** 2.0.0 (Rigorous MVP)  
**Статус:** Глубокая переработка с физическим смыслом  

---

## Новая архитектура

В соответствии с новыми требованиями, проект был переработан для обеспечения строгого физического моделирования и разделения ответственности.

### Структура проекта

```
elou_avt_twin/
├── calculation_core/        # НОВОЕ: Слой физических расчётов
│   ├── thermodynamics/      # VLE, Flash (Rachford-Rice), Antoine, Enthalpy, Cp
│   ├── material_balance/    # Проверка сохранения массы
│   ├── energy_balance/      # Проверка сохранения энергии
│   ├── hydraulics/          # Darcy-Weisbach, Valve Flow
│   ├── solver/              # Численные решатели (MESH)
│   └── validation/          # Проверка физической корректности
├── models/
│   ├── stream.py            # НОВОЕ: Унифицированная модель потока (Stream)
│   └── base.py              # SimulationState, SimulationConfig
├── equipment/               # Обновлено: Оборудование с Stream-интерфейсом
│   ├── pump.py              # Насос с расчётом мощности и нагрева
│   ├── valve.py             # Клапан с гидравлическим расчётом
│   ├── heater.py            # Печь с балансом горения
│   ├── distillation_column.py # Колонна на базе MESH-модели
│   └── elou.py              # ЭЛОУ с балансом солей и воды
├── simulation_core/         # Оркестрация и API
└── tests/                   # Строгие тесты физики
```

## Ключевые изменения

### 1. Унифицированная модель потока (`Stream`)
Все связи между оборудованием теперь используют объект `Stream`, который содержит:
*   Температуру [K] и Давление [Pa]
*   Массовый [kg/s] и Молярный [mol/s] расходы
*   Состав (массовые доли компонентов)
*   Термодинамические свойства (Энтальпия, Плотность, Вязкость)
*   Фазовое состояние (LIQUID, VAPOR, TWO_PHASE)

### 2. Строгая термодинамика
Реализован модуль `calculation_core/thermodynamics/`, обеспечивающий:
*   **VLE (Vapor-Liquid Equilibrium)**: Расчёт фазового равновесия методом Рачфорда-Райса.
*   **K-values**: Расчёт констант равновесия на основе уравнения Антуана.
*   **Энтальпия и Теплоёмкость**: Зависимость от температуры и состава (полиномы).
*   **Плотность**: Расчёт для газа (Идеальный газ) и жидкости (с учётом теплового расширения).

### 3. Балансы и валидация
Добавлен `balance_checker.py`, который автоматически проверяет:
*   `mass_balance_error` (ΣIn - ΣOut = dM/dt)
*   `energy_balance_error` (ΣH_in - ΣH_out + Q + W = dU/dt)
*   Физические границы (температура > 0, давление > 0, сумма долей = 1).

### 4. Доработка оборудования
*   **Pump**: Расчёт потребляемой мощности и приращения энтальпии потока.
*   **Valve**: Расчёт расхода на основе перепада давления и Cv.
*   **Heater**: Связь расхода топлива с тепловой нагрузкой и энтальпией продукта.
*   **Distillation Column**: Переход к многостадийной модели (MESH).
*   **ELOU**: Учёт эффективности удаления солей и воды.

## Интерактивная web-схема (React)

Frontend-редактор технологической схемы живёт в отдельной папке `elou_avt_web/`
(Vite + React + React Flow). Он подключается к этому же API через Vite-прокси
(`/state`, `/history`, `/scheme`, `/action`, `/input`, `/scenario`, `/failure`,
`/ws/simulation` → `127.0.0.1:8000`).

Запуск (после установки `npm install`):
```bash
cd elou_avt_web
npm run dev          # → http://localhost:5173
```

Возможности:
*   drag&drop сборка схемы из палитры объектов, соединение по портам;
*   live-телеметрия по WebSocket (расходы, температуры, давления);
*   клик по объекту → инспектор с параметрами и управлением (пуск/стоп насоса,
    позиция клапана, топливо печи, флегмовое число, граничные условия источника);
*   инъекция отказов и запуск сценариев;
*   тренды параметров за последние 10 минут;
*   сохранение/загрузка схемы как JSON-графа на бекенде (`schemes/process_elou_avt.json`).

## Допущения и TODO
1.  **Thermodynamics**: Для MVP используется модель идеальной смеси. Для промышленной точности требуется внедрение EOS (например, Peng-Robinson).
2.  **MESH Solver**: В текущей версии реализован каркас многостадийного расчёта с упрощённым разделением. Требуется внедрение полного метода Ньютона-Рафсона для решения системы MESH-уравнений.
3.  **Hydraulics**: Модель давления в системе требует внедрения полноценного гидравлического решателя для разветвлённых сетей.
