1. КАРТА ФИЗИЧЕСКОЙ МОДЕЛИ
--------------------------------------------------------------------------------
Для каждой модели указаны: файл:строки, уравнение, единицы, область применимости.

1.1 Stream (models/stream.py)
  - temperature [K], pressure [Pa], mass_flow [kg/s], molar_flow [mol/s],
    volumetric_flow [m3/s], enthalpy [J/kg], density [kg/m3], viscosity [Pa*s],
    composition = МАССОВЫЕ доли {id: fraction} (stream.py:30).
  - Pydantic-валидация: T>0, P>0, m>=0; композиция нормируется только если
    сумма вне [0.99, 1.01] (stream.py:36-46). validate_physics(): T в [200,2000] K,
    P в [100, 1e8] Pa, фракции в [0,1] (stream.py:48-56).
  - Пробелы: нет обязательной проверки «сумма фракций = 1» на входе; enthalpy и
    density не обязаны соответствовать (T,P,composition) — согласованность
    поддерживается вручную в equipment.

1.2 Компоненты / Composition
  - MVP-набор COMPONENTS (components.py:7-39): oil, water, salt, naphtha с
    molar_mass [kg/mol], antoine A/B/C, cp_coeffs, rho_ref. Используется ТОЛЬКО
    в тестах (test_rigorous.py:9).
  - Рабочий набор FRACTION_COMPONENTS (fractions.py:151-161): 7 нефтяных фракций
    (frac_nk62 … frac_mazut) + water + salt. Критические свойства (Tc, Pc, omega,
    MW) получены интерполяцией по n-алкановой таблице по NBP (fractions.py:27-69),
    MW по Riazi-Daubert (fractions.py:86-90).
  - ДВА независимых набора данных компонентов — риск рассинхрона (P2).

1.3 Термодинамика
  - Абстрактный ThermodynamicModel (base.py:5-31): calculate_enthalpy [J/kg],
    calculate_density [kg/m3], calculate_cp [J/(kg*K)], calculate_vle -> (beta,
    x_mass, y_mass).
  - IdealThermodynamics (base.py:33-70): H = Cp(T)*(T-T_ref), Cp из полинома по
    МАССОВЫМ долям, плотность жидкости rho_ref*(1 - alpha*(T-298.15)),
    пар — идеальный газ. VLE делегируется vle.py. Используется в тестах.
  - PengRobinsonThermodynamics (pr_eos.py:100-593) — РАБОЧАЯ модель движка
    (engine.py:103-105). PR-уравнение: Z^3 - (1-B)Z^2 + (A-3B^2-2B)Z - (AB-B^2-B^3)=0,
    A=am*P/(R^2 T^2), B=b*P/(RT). К-значения из фугасити: K_i = phi_i(L)/phi_i(V)
    (pr_eos.py:331-336). Энтальпия = ideal-gas (полином Cp) + residual PR
    (pr_eos.py:201-226), включает скрытую теплоту. density: пар — PR-молярный
    объём (pr_eos.py:299-303), жидкость — SG с тепловым расширением (не
    volume-translated, занижение 10-20% отмечено в комментарии). PT-flash:
    Wilson-инициализация + successive substitution (pr_eos.py:364-396).

1.4 VLE
  - vle.py (Ideal/Raoult-ветка): K_i = Psat_i/P, Psat из Antoine
    log10(P[Pa]) = A - B/(T+C) (vle.py:5-25); flash через Rachford-Rice с
    конвертацией масс->моль->масс (vle.py:33-92).
  - pr_eos.flash_molar: стабильность по Wilson-суммам, RR-бисекция, обновление K
    фугасити-отношениями (pr_eos.py:364-396).
  - Согласованность: обе реализации возвращают (beta, x_mass, y_mass).

1.5 Энтальпия
  - PR: H_molar = Cp_ig(T) + H_residual(T,P,z) (pr_eos.py:224-226); удельная
    [J/kg] = H_molar / Mw (pr_eos.py:249-250). temperature_from_enthalpy —
    бисекция H(T) с фикс. диапазоном [200,1200] K (pr_eos.py:252-271).

1.6 Плотность
  - PR: пар — PR-молярный объём; жидкость — SG*1000*(1 - alpha*(T-288.15)),
    alpha=0.0008 (pr_eos.py:305-308). MVP-ветка — base.py:56-66.

1.7 Теплоёмкость
  - Ideal: полином по масс. долям (base.py:40-48). PR: конечные разности
    энтальпии с шагом d=0.5 K (pr_eos.py:273-284); внутри двухфазной области даёт
    «эффективный Cp» с латентной теплотой.

1.8 Гидравлика (calculation_core/hydraulics/pressure_drop.py)
  - Труба: Darcy-Weisbach dP = f*(L/D)*(rho*v^2/2); f=64/Re при Re<2300, иначе
    Haaland (pressure_drop.py:4-25). Условно SI.
  - Клапан: Q = Cv*opening*sqrt(dP/rho) [m3/s], линейная характеристика
    (pressure_drop.py:27-37). Cv — «SI-условный» (комментарий: не галлоны).

1.9 Насос (equipment/pump.py)
  - W = V_flow*dP/eta, work_per_mass = W/m (pump.py:48-50); напор номинальный,
    кривая насоса НЕ используется (есть дублирующая calculate_pump_head в
    equations.py:17-24 — dead code). При остановке/отказе выход 0 (pump.py:31-35);
    кавитация обрезает поток на 50% (pump.py:45-46).

1.10 Клапан регулирующий (equipment/valve.py)
  - Позиция — инерция первого порядка с response_rate (valve.py:35-39).
  - Пропуск: mass_flow = min(cap, m_in); cap из calculate_valve_flow
    (valve.py:58-61). dP = 0.05*design_dp + design_dp*restriction (valve.py:65-66).
    Back-pressure: p_in_eff = p_in + design_dp*restriction (valve.py:69).
  - current_capacity() — для dead-heading апстрима (valve.py:83-94).

1.11 Печь (equipment/heater.py)
  - Q = m_fuel*LHV*eta, ограничение max_duty (heater.py:57-58); инерция fuel_flow
    с tau (heater.py:52-53). H_out = H_in + Q/m (heater.py:63); T_out через
    temperature_from_enthalpy (rigorous) или Cp-приближение (heater.py:64-75).
    Отказ = флеймаут (heater.py:44-49).

1.12 Теплообменник (equipment/heat_exchanger.py)
  - Эффективность-NTU counter-flow: eps = f(NTU, cr), Q = eps*c_min*dt_max
    (heat_exchanger.py:60-72); H-балансы и T_out через temperature_from_enthalpy
    (heat_exchanger.py:74-96). Нет учёта фазовых переходов/конденсации в NTU.

1.13 Колонна (equipment/distillation_column.py + mesh_solver.py)
  - MESH: M — тридиагональные покомпонентные балансы (mesh_solver.py:105-130);
    E — y=Kx (Wilson/PR); S — bubble point sum Kx=1 (bubble_temperature_vec);
    H — энергобалансовый проход L/V сверху вниз (mesh_solver.py:136-165), без
    допущения CMO. D определяется из top_cut/feed-композиции (mesh_solver.py:211-229),
    B = F - D. Демпфирование T (omega=0.3), tol эффективная 0.3 K
    (mesh_solver.py:293-299). Fallback на массосохраняющий split при несходимости
    (distillation_column.py:106-153). Масштабирование мольных потоков к массе
    feed (distillation_column.py:158-168). Stage 1 = total condenser, N = reboiler.
  - Параметры в схеме: K-1..K-12, num_stages 4..30, nominal_pressure
    58839.9..784532 Pa, top_cut по фракциям.

1.14 ЭЛОУ (equipment/elou.py)

1.15 Буферный танк (equipment/tank.py)

4. КЛЮЧЕВЫЕ ВЫВОДЫ / РИСКИ
--------------------------------------------------------------------------------
4.1 Сохранение массы: точечно соблюдается в tank (с клампом), в pump/valve
    (передача потока), в колонне (fallback D+B=F), в ЭЛОУ — нарушено
    покомпонентно для соли/воды (F02), при переполнении tank (F07), при
    смешении/делении потоков (F10 — композиция нормируется, но водяной/соляной
    компоненты при делёже в fork делятся поровну как массовая доля — ок,
    масса сохраняется при равном делёже).
4.2 Сохранение энергии: балансы локальные; глобально не проверяются (F03).
    Энтальпия после изменения comp/T не всегда пересчитывается (F11).
4.3 Размерности: в целом SI; дыры — F08 (valve standalone), F17 (Antoine),
    F18 (Т_ref балансов), F23 (R).
4.4 Сходимость: MESH-солвер — главный источник нефизичных результатов в
    прогонах (F04); fallback скрывает, но даёт «ступенчатые» температуры.
4.5 Перегрев печи (F05) — критично для аварийной логики тренировочного симулятора.

6. РЕКОМЕНДАЦИИ ПО ТЕСТАМ (для PHASE 7)
--------------------------------------------------------------------------------
- Унитарные: Psat(water, 373.15 K) ~ 101325 Pa (Антуан/PR Wilson) — привязка к
  справочнику; PR-плотность воды ~1000 kg/m3 при 293 K; энтальпия воды при
  кипении = h_v - h_l ~ 2.26e6 J/kg (латентная теплота в PR-разности).
- Flash: материальный баланс beta*x + (1-beta)*y = z (мольн. и масс.);
  нормализация x, y, z = 1.
- Колонна: D+B=F покомпонентно (масс. и мольн.); конденсатор/рибойлер:
  Q_cond = V*(hV - hL); профиль T монотонен сверху вниз; суммарный
  энергобаланс колонны |Σ_in H - Σ_out H + Q_reb - Q_cond|/F_h < tol.
- Движок: смешение/делёж сохраняют массу (покомпонентно); уровень tank
  с overflow; dead-head (клапан закрыт) -> src остаётся на задании, tank
  накапливает (регрессия на сценарии valve_FV1/pump_H1).
- Smoke: число аварий не должно расти vs базовый прогон; furnace T < уставки.
- Производительность: 300 шагов < 120 s (текущий прогон ~6 мин — ускорить
  солвер: PR-векторизация частично есть, измерить hot spots).

PHASE 2 — ЕДИНЫЙ СЛОЙ UNITS И СТРОГАЯ СЕМАНТИКА STREAM
--------------------------------------------------------
1) calculation_core/units.py (НОВЫЙ файл) — канонические единицы:
   - Константы: KELVIN_ZERO_C=273.15, BAR_TO_PA=1e5, ATMOSPHERE_PA=101325.
   - celsius_to_kelvin / kelvin_to_celsius / bar_to_pa / pa_to_bar.
   - mass_to_mole_fractions (x_i=(w_i/M_i)/Σ), mole_to_mass_fractions;
     НЕИЗВЕСТНЫЙ компонент -> ValueError (без фейковых Mw).
   - mean_molecular_weight = 1/Σ(w_i/M_i) [кг/моль] (тождество
     mass_flow = molar_flow * Mw).
   - mass_to_molar_flow / molar_to_mass_flow / mass_to_volumetric_flow /
     volumetric_to_mass_flow.
   - Каждая функция: формула, физ. смысл, единицы, область применимости.
   Канонический набор: K, Pa, kg/s, mol/s, m^3/s, J/kg, W, kg/m^3,
   J/(kg·K), kg/mol, Pa·s, s.

2) models/stream.py — контракт composition (F01):
   - composition — ВСЕГДА массовые доли, сумма ОБЯЗАНО = 1.0.
   - Сумма вне [1-1e-6, 1+1e-6] -> ValueError. Тихая нормализация
     УДАЛЕНА (прежний validator нормировал состав — это маскировало
     ошибки баланса).
   - Отрицательные доли -> ValueError.
   - Новые методы: mole_fractions(mw), mean_molar_mass(mw),
     validate_consistency(mw=None) — кросс-проверка mass<->molar<->volumetric
     (пропускает None-поля).

PHASE 3 — ПРАВКИ ЯДРА ТЕРМОДИНАМИКИ И ОБОРУДОВАНИЯ
---------------------------------------------------
3) pr_eos.py (F13 + строгие компоненты + устойчивый bubble/dew):
   - _names: неизвестный компонент -> ValueError (раньше молча отбрасывался).
   - _require_names + вызов в k_values_wilson/flash_molar: прямой вызов с
     неизвестным id -> ValueError, а не KeyError.
   - _nonvolatile_mask: в k_values (PR fugacity) соль и прочие volatile=False
     ПИНУЮТСЯ в жидкость (K=1e-10) — в flash соль никогда не попадает в пар.
   - bubble_temperature/dew_temperature переписаны: выше Tc PR даёт K=1
     (плоский корень кубики), поэтому старый монотонный поиск застревал на
     верхней границе (вода: 1200K вместо 373K). Теперь первое пересечение
     знака ищется скан-сеткой 61 точки + бисекция в брекете. Проверено:
     PR NBP воды = ~377K (|Δ|<3K от 373.15), латентная теплота ~2.4e4 J/mol
     (порядок корректный).

4) base.py IdealThermodynamics (F11):
   - calculate_enthalpy = ТОЧНЫЙ интеграл ∫Cp dT =
     a(T-T0) + b/2(T²-T0²) + c/3(T³-T0³), T0=298.15. Раньше H=Cp(T)(T-T0)
     (аппроксимация) — расходилась с Cp(T). H(298.15)=0.
   - calculate_cp/calculate_density: неизвестный компонент -> ValueError
     (раньше дефолты 2000/850/0.1 молча искажали результат).

5) valve.py (F08): standalone-ветка (inlet=None) использует ТУ ЖЕ формулу
   Q = Cv*x*sqrt(dP/rho) с rho=850 (раньше Q=Cv*x*sqrt(dP) — терялся
   множитель 1/sqrt(rho)).

6) elou.py (F02 + F11):
   - Покомпонентный баланс: removed_salt = m*salt_in*eff_salt,
     removed_water = m*water_in*eff_water (массовые доли ОТ ВСЕГО потока).
   - Выход: композиция = остаток соли/воды + все углеводороды, нормировка.
   - Brine: ТОЛЬКО реально удалённые соль+вода (+ wash) с реальными долями
     (раньше dummy {0.1, 0.9} — рвал баланс). Проверка тестом:
     m_in*w_i == m_oil*w_i + m_brine*w_i для salt и water; сумма выходов = вход.
   - При наличии thermo: энтальпия outlet/brine пересчитывается по новой
     композиции (F11) — не тащится энтальпия старого состава.
   - Краевой случай salt=water=0: brine = {water:1.0} с m=0 (валидный Stream).

7) heater.py (F05):
   - max_outlet_temp (по умолчанию 1000 K) — физический предел (трубы).
   - При T_out > предела НЕ «потолок» с разрывом энергобаланса: duty
     ужимается так, что H_out(T_max) = H_in + Q/m точно
     (пересчёт через calculate_enthalpy). Флаг duty_limited.
   - Эффект: furnace_P3 в smoke был ~1200K (HIGH-HIGH), стал 1000K.
     Примечание: реальные AVT-печи работают ~350–380°C (уставка furnace_P3
     HIGH-HIGH=653.15K) — предел и топливные уставки сценария калибровать
     в PHASE 4 (печь физически перегрета из-за большого fuel_flow).

8) tank.py + simulation_core/engine.py (F07):
   - tank.step: overflow — масса выше height не уничтожается, а добавляется
     к выходу (spill); тест: d_stored + m_out == m_in.
   - engine._attach_level (column/elou/separator): уровень клампится на
     height, но избыточная масса учитывается как overflow_mass (объём*rho)
     — те же гарантии на уровне схемы.
