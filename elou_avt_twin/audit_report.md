# Аудит существующего проекта `elou_avt_twin`

## 1. Общие требования и текущая реализация

**Требование:** Каждый расчётный модуль должен иметь физический смысл, чёткие входные/выходные данные, единицы измерения, ограничения применимости, обработку ошибок, автоматические тесты, проверку размерности и физических ограничений. Если данных недостаточно, явно указывать, использовать конфигурируемые параметры, добавлять TODO и использовать упрощённые модели только как явно обозначенный MVP-режим.

**Текущая реализация:** Существующий код в целом следует этим принципам на уровне MVP. Многие функции и классы имеют комментарии с `[MVP SIMPLIFICATION]`, указывающие на упрощения. Однако, с переходом к более строгой физической модели, потребуется значительно углубить детализацию, добавить явные проверки и более сложные расчёты.

**Пробелы:**
*   Отсутствует единая модель потока (`Stream`) с валидацией.
*   Балансы (материальный, энергетический) не проверяются автоматически на сходимость.
*   Обработка ошибок внутри физических расчётов минимальна.
*   Проверки размерности и физических ограничений не реализованы.

## 3. Целевая архитектура и рефакторинг

**Текущая архитектура:** `Digital Twin Engine` и `Equipment Models` реализованы. `Calculation Core` частично присутствует в `physics/` и внутри классов оборудования.

**Целевая архитектура:** Требуется выделение `Calculation Core` как отдельного слоя с подмодулями `models/`, `thermodynamics/`, `material_balance/`, `energy_balance/`, `hydraulics/`, `heat_transfer/`, `solver/`, `validation/`.

**План рефакторинга:**
1.  Создать новую директорию `calculation_core/`.
2.  Перенести и переработать функции из `physics/equations.py` и `physics/process_physics.py` в соответствующие подмодули `calculation_core/`.
3.  Разработать новый модуль `thermodynamics/` для VLE, K-values, Flash Calculation (Rachford-Rice), возможно, с интерфейсом для EOS (Peng-Robinson).
4.  Разработать модули `material_balance/` и `energy_balance/` для явной проверки балансов.
5.  Модули `solver/` и `validation/` будут заполнены соответствующими функциями.
6.  Обновить классы оборудования (`equipment/`) для использования функций из `calculation_core/` и новой модели `Stream`.
7.  Обновить `SimulationEngine` для оркестрации `CalculationCore` и `Equipment Models`.

## 4. Единая модель потока (`Stream`)

**Требование:** Создать унифицированную модель технологического потока (`Stream`) с полями для температуры, давления, массового/молярного/объёмного расхода, состава, фазы, энтальпии, плотности, вязкости. Строгая проверка единиц измерения, диапазонов, суммы компонент, отрицательных расходов, давления, температуры, состава. Единая система единиц (K, Pa/bar, kg/s или mol/s, W, J/kg или J/mol).

**План реализации:**

**План реализации:**
1.  Создать модуль `calculation_core/material_balance.py`.
2.  Реализовать функции для расчёта и проверки общего и компонентного материального баланса для аппаратов.

## 6. Энергетический баланс

**Требование:** Реализовать общий энергетический баланс (`dU/dt = Q + Σ(H_in) - Σ(H_out) + W`). Учесть теплообменники, печь, испарение, конденсацию, тепловые потери, изменение энтальпии. Не использовать постоянную теплоёмкость. Сделать интерфейс `enthalpy(T, P, composition)`, `cp(T, P, composition)`, `density(T, P, composition)`.

**План реализации:**
1.  Создать модуль `calculation_core/energy_balance.py`.
2.  Реализовать функции для расчёта и проверки энергетического баланса.
3.  Интегрировать с новым модулем `thermodynamics/` для получения `enthalpy`, `cp`, `density`.

## 7. Термодинамика

**Требование:** Создать интерфейс `ThermodynamicModel`. Минимальный MVP должен поддерживать VLE, K-values, Bubble Point, Dew Point, Flash Calculation (Rachford-Rice). Для MVP можно использовать Antoine для простых компонентов. Если Peng-Robinson реализуется, добавить EOS, fugacity coefficients, phase equilibrium, K-values. Если полноценная EOS выходит за рамки, сделать интерфейс и отметить ограничение.

**План реализации:**
1.  Создать модуль `calculation_core/thermodynamics.py`.
2.  Определить интерфейс `ThermodynamicModel`.
3.  Реализовать `Rachford-Rice` для Flash Calculation.
4.  Реализовать упрощённые K-values (например, на основе Antoine или корреляций) для MVP.
